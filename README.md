# Backend Bus

## Internal wallet balances

Payment methods expose `balance` in integer VND. This is internal demo credit;
there is no connection to MoMo/bank balances or real provider payments.
New methods start at 0. Client create/update payloads cannot set `balance`.
New seed fixtures start at 80,000 VND. To initialize **existing test accounts**
that have no stored balance, or an unfunded 0 balance, run
`npm run seed:wallet-balances` once. Normal seed also initializes these existing
test wallets. This only touches users listed in `RAW_USERS`; positive balances,
already initialized balances and wallets with recorded debits are preserved.
`balanceInitializedAt` prevents repeatedly granting opening credit, even after
it is spent. Historical seeded tickets are not re-charged. No `seed:fresh` is needed.

`POST /api/tickets/create` accepts a `purchaseKey` (16–128 ASCII letters,
digits, `_` or `-`). Updated clients send the same key when retrying the same checkout.
For compatibility, missing keys are generated by the server. Legacy clients
without a key cannot deduplicate separate HTTP retries and should be updated.
Invalid explicit keys are rejected. The server
calculates the fare from its ticket product, checks ownership and sufficient
balance, and atomically debits the selected method and creates the paid ticket.
Repeating a key returns the same ticket; changing the purchase with that key is
rejected. A failed ticket insert rolls back the debit. `balanceAfter` on the
ticket records the post-payment balance. MongoDB Atlas or a replica set is
required for transactions; no non-transactional fallback is used.

The Payment tab refreshes the method balance when focused. Spending history
continues to display purchased tickets separately. Example: 80,000 VND balance
minus an 8,000 VND ticket leaves 72,000 VND.

Checks: `node --test test/walletPurchase.test.js`.

To repair passwords from an older seed that hashed them twice, run
`npm run seed:repair-passwords`. This resets existing accounts listed in
`RAW_USERS` to their documented test passwords, preserving user IDs and related
data. Normal `npm run seed` preserves existing passwords. Do not use `seed:fresh`
for this repair; it deletes collections.

Password seed regression checks: `node --test test/seedUsers.test.js`.

## Location suggestions

`POST /api/suggest-locations` accepts `{ "keyword": "san bay" }` and returns
`data: [{ display_name, lat, lng }]`. Bus stops are matched without Vietnamese
diacritics, using MongoDB or bundled route data when the database is unavailable.
Additional places come from [Photon](https://github.com/komoot/photon), which
supports search-as-you-type. Set `PHOTON_API_URL` to a private Photon `/api/`
endpoint if needed; the default demo server has no availability guarantee.
Remote results are cached for five minutes (up to 100 queries).
If Photon fails, matching stops are still returned. When no fallback matches,
the API returns 503 so clients can display a retry message.

Regression checks: `node --test test/suggestLocation.test.js`.

Node.js (Express + Mongoose) API cho User và Post.

## Cấu trúc dự án

```
backend-bus/
├── config/          # Cấu hình (DB, env)
├── controllers/     # Xử lý request/response
├── middlewares/     # Auth, ...
├── models/          # Mongoose models (User, Post, Otp)
├── routes/          # Định tuyến API
├── services/        # Business logic
├── utils/           # OTP storage, email
├── validations/     # express-validator
├── app.js
├── server.js
└── .env.example
```

## Chạy dự án

```bash
npm install
cp .env.example .env   # Sửa .env
npm run dev
```

## API

### User

| Method | Endpoint | Mô tả |
|--------|----------|-------|
| POST | /api/users/register/send-otp | Gửi OTP đăng ký |
| POST | /api/users/register/verify-otp | Xác nhận OTP và tạo tài khoản |
| POST | /api/users/login | Đăng nhập |
| PUT | /api/users/profile | Cập nhật thông tin (cần token) |

### Post

| Method | Endpoint | Mô tả |
|--------|----------|-------|
| POST | /api/posts | Tạo post (auth) |
| PUT | /api/posts/:id | Sửa post (auth) |
| DELETE | /api/posts/:id | Xóa post (auth) |
| GET | /api/posts | Danh sách (pagination, search, sort) |
| GET | /api/posts/:id | Chi tiết 1 post |

**Query params cho GET /api/posts:**
- `page`, `limit` – phân trang
- `search` – tìm trong title, content, summary
- `sort` – `newest` (mặc định) hoặc `oldest`
